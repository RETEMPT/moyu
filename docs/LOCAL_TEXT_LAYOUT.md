# 系统识别与本地排版规则

更新：2026-10-16。系统 OCR 保留，整理不依赖在线生成服务。产品边界见 [当前声明](../PRODUCT_SCOPE.md)。

## 资料依据与实现选择

| 原始资料 | 借鉴内容 | 当前实现 |
| --- | --- | --- |
| [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) | 代码围栏匹配、标题、列表与硬换行的结构边界 | 共享块扫描；代码与公式先保护，再整理正文。围栏须满足字符、长度和闭合条件；支持 Setext 标题，并保留 `C#` 这样的标题文字 |
| [GFM 任务列表](https://github.github.com/gfm/#task-list-items-extension-) | 显式未完成项与已完成项区别 | 识别明确未完成勾选项，保存原文行号，排除已完成项，用户选择后才保存待办 |
| [Unicode UAX #14](https://www.unicode.org/reports/tr14/) | 强制行分隔和段落分隔不能当作任意可合并换行 | 普通正文行分隔符转为明确硬换行，段落分隔符保留空段；代码、公式与表格字面内容保留；合并时不消除边界处的不换行空格与连接符 |
| [ICU 边界分析说明](https://unicode-org.github.io/icu/userguide/boundaryanalysis/) | 合法折行位置与选择实际行宽是不同任务 | 工程只做资料结构整理，实际字体测量和屏幕折行交给 ArkUI，不在文本中猜测设备行宽 |

上述为规范依据的自有规则实现，没有复制第三方库。并未实现完整 CommonMark 渲染器或完整 Unicode 换行算法；尤其不能仅凭纯文字保证多栏 PDF 阅读顺序正确。

## 使用流程

1. 从系统 OCR、PDF 文字层或普通 Markdown／TXT 得到文字。设备不支持 OCR 时可粘贴输入。
2. 校对姓名、数字、日期、公式和阅读顺序。保留校对原文，排版正文单独编辑。
3. “保留原文”保持顺序和段落；“学习笔记”只整理明确标题与项目符号。
4. 断行合并默认关闭。开启后，只连接符合条件的普通正文，不跨空段、标题、列表、引用、代码、公式、表格或硬换行。
5. 待办逐项选择，检查原文位置和日期；模糊日期须修改或取消勾选，空日期明确表示加入今天。

## 验证用例

工作流检查覆盖多种围栏、代码／公式／表格保留、未闭合围栏、OCR 断行、Unicode 行与段落分隔、Setext 与 ATX 标题、`C#` 标题尾部、格式幂等、原文证据、否定条件、日期歧义、跨日草稿和超限输入保护。

系统识别结果只有在所有非空白字符及顺序一致时才采用 SDK 返回的块段落。读取后释放临时图像，取消和超限不覆盖原输入。实际识别准确率、原生排版与流畅度仍需要支持设备验证。
