# 调试内置 PDF 验证（2026-10-10）

调试版启动后在“示例资料”加入“墨语阅读测试.pdf”。原件复制到应用 documents 目录，保存文件名、真实两页内容和独立笔记 ID；不会替换旧版缺少原件的九页记录及其批注。固定 ID 和持久标记避免启动重复添加，回收站及主动删除也不会触发重建。笔记快照保存失败会清理未提交的示例副本，原资料保留。

当前 Windows Pad 模拟器未提供 `SystemCapability.OfficeService.PDFService.Core`，此前直接构造 PdfDocument 报 undefined。现按系统能力选择路径：支持设备继续使用 PDF Kit 解析及渲染；调试版在缺少能力时只对与两份内置原件逐字节一致、位于应用 documents 中的文件使用 Poppler 预渲染 PNG。页面号限定为两页。文件名相同、字节修改或其他目录的文件均不能误用预览。PDF 文字提取仍需要 PDF Kit，不用笔记元数据冒充原文。

`entry/build-profile.json5` 的 release 资源排除规则剔除两份测试 PDF 和 `debug-pdf-preview` 图片；发布代码不注入示例、不接受测试导入、不显示测试入口。已存在的应用资料不被发布构建自动删除。

验证结果：

- SDK debug 与 release HAP 构建通过，保留原有框架弃用警告。release HAP 的 ZIP 内容检查没有两份测试 PDF 或预览图片；最终本机构建产物恢复为 debug。
- 365 项工作流、43 项 PDF 专项、7 项 SDK 编译后 UI、11 项发布规则通过。PDF 新增检查涵盖缺失原生组件、原件逐字节校验、目录及页码限制、release 禁用、一次注入、删除/回收站、快照失败清理。
- 两份原件结构与四张预渲染图片检查通过，中文、英文、符号及页码显示完整；快照版确认无文字层。
- 对 `127.0.0.1:5555` 执行覆盖安装，保留原应用数据。实际读取到一份两页示例和本机 sourceFileName；模拟器打开两页内容、翻页与进入批注工具栏正常。
