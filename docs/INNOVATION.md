# 墨语的产品特点与创新方向

墨语围绕原件、个人理解与复习组织学习过程。它将不同格式的资料放在共同的研读工作台中，让阅读、书写、整理和再次使用之间保持联系。

## 产品特点

**跨格式研读。** 文字笔记、PDF、图片与手写内容采用一致的文件标签和工作台，支持对照阅读。各区域保持自身的编辑与保存逻辑，减少应用间切换和重复定位。

**原件与理解分离。** 原PDF和图片保留，笔迹、稿纸与校对文字独立保存。用户既能保留自己的理解，也能随时回到资料依据。

**逐步整理。** OCR结果经过人工校对，本地排版保留原文和预览。整理并不要求一次完成，使用者可以在阅读过程中持续修订。

**连接记录与复习。** 随手记成为可检索的笔记，项目、标签和双链帮助组织内容，题卡让已经研读的材料进入自测过程。

这些特点对应现有的阅读工作台、保存策略、检索与复习服务，具体实现见[架构](ARCHITECTURE.md)。

1.1.1 进一步补齐本地学习概况与题卡修订：依据真实阅读位置和最近自测反馈汇总，按当前资料分类组织待巩固项，到期弱项优先，编辑问题和答案时保留复习安排。它仍是可解释的本地规则，不用阅读百分比替代掌握判断；手机和平板实际交互仍待验证。

## 未来的创新方向

| 方向 | 设计思路 | 希望解决的问题 |
| --- | --- | --- |
| 可追溯云AI | 将摘要、问答与题卡候选绑定原文版本和引用 | 让生成结果能够被核对、修改和继续使用 |
| 资料与学习成果关联 | 在原件、笔记、整理结果和题卡之间保留关系 | 降低重复整理和查找出处的负担 |
| 公开发现与私人研读衔接 | 从授权资料库发现内容，再进入个人工作台 | 连接内容获取与深入学习 |
| 可靠的跨设备延续 | 结合可选存储、版本信息和冲突处理 | 适应不同设备和学习阶段 |
| 按场景使用的云服务 | 围绕明确资料任务提供处理能力 | 让服务与具体学习成果直接相关 |

云AI、资料平台和跨设备连接的具体方向分别见[云AI学习服务](CLOUD_AI_BUSINESS.md)、[资料平台规划](WEB_PLATFORM_PLAN.md)和[未来开发方向](ROADMAP.md)。

## 设计与验证

产品改进以真实任务为依据：观察资料能否被顺利打开，笔迹和记录能否找回，整理结果是否便于修改，以及复习时能否回到原文。云AI进一步关注引用是否支持回答、资料变化如何处理，以及人工修正与采纳的负担。

Notion的文档布局、Koodo的阅读流程和Memos的本地记录方式提供了研究参考。墨语的实现围绕鸿蒙原生交互、跨格式协调和资料归属展开，参考与复用边界见[参考研究](KOODO_REFERENCE.md)和[依赖说明](DEPENDENCIES.md)。
