# AI 输入菜单与 PDF / 白板链路检查

依据用户提供的 Pad 截图与交互反馈。本文记录实现与测试范围；真机触控和原生能力验收需另行记录。

## 交互与设计

墨客输入框的加号使用 ArkUI 原生锚定菜单，优先显示资料库引用、外部文件导入和图片文字识别，已有引用时可移除引用。模型选择独立放在输入区，助手配置从模型菜单进入；新建对话独立置于顶栏更多左边，撤回和删除在更多菜单。原生 Button 用显式布尔状态与直接具名 Builder 绑定菜单，外点/选择/返回均关闭状态；不得再使用未被 SDK 转换的箭头 Builder 包装。文档更多支持随堂稿纸、AI 伴读及仅正文。菜单跟随实际工作区宽度，优先在触发器上方展开，由系统在空间不足时调整位置。保持统一 SVG 图标、主题颜色和至少 44vp 的操作区域。

参考的是入口分工，不是逐像素复制：[OpenAI 官方功能说明](https://learn.chatgpt.com/docs/features)、[Claude Code 桌面版](https://code.claude.com/docs/en/desktop)、[Claude Code 编辑器集成](https://code.claude.com/docs/en/vs-code)。原生 API 兼容性通过本地 SDK 与实际 ArkTS 构建检查；手机键盘、横竖屏和 Pad 分栏的具体位置需设备验证。

## PDF 原件与批注

- 旧示例只有元数据和页数，不能恢复不存在的 PDF。错误页显示具体原因及“重新关联原 PDF”，不再对空白错误占位落笔；没有原件时不显示无效的重试按钮。
- 导入先复制到应用沙箱，核对文件长度并同步写入，再通过 PDFKit 解析真实页数、渲染首页、释放预览位图，成功后才写入资料库。备份恢复使用同一验证过程。
- 重新关联需要用户选择该资料原件，保持笔记 ID 和现有批注；有批注时拒绝不一致页数。相同页数不能证明内容相同，选择前明确提示检查笔迹对应关系，旧文字索引清除后可重新提取。失败清理新副本，保留原记录和原件；成功后仅清理没有任何笔记或回收站引用的旧应用副本。
- 当前页原件渲染成功后才允许批注。正在加载或错误页的墨水层关闭命中，不遮挡恢复按钮；不可见页释放位图。
- 顶栏返回、系统返回和退出批注按钮均先结束当前笔画/橡皮操作、保存并恢复只读，留在原文件和当前页。再次返回才关闭资料；未保存内容保留重试入口。手机默认可用手指批注，Pad 默认笔写，可主动切换手指书写。
- 翻页、工具切换、手指开关及连续/单页切换同步结束接触；取消接触不产生不可撤销的半次擦除。保存完成带笔记 ID 和请求令牌，旧回调不能关闭后来打开的文档。

## 白板与稿纸

全屏阅读器在批注模式隐藏五个阅读选项，以一组紧凑工具操作正文或稿纸；嵌入画布关闭自身工具栏，独立白板保留工具栏。工具状态通过回调和子组件 @Prop 同步，命令携带序号与目标，另一画布不响应。默认手指可写，双指平移缩放；笔输入优先且过滤手掌和无关触点。白板落笔末尾靠近边缘时揭示更多区域，双指末尾抬起及取消均释放导航状态。

活动橡皮在视口重绘时保留当前擦除路径；撤销、重做与清空先结束当前笔画。清空确认过期不能作用于另一篇笔记或已回到只读的画布。白板标题、正文、预览和主笔迹按自身字段保存，稿纸保存不覆盖主内容、收藏和分类。

白板/稿纸和 PDF 均支持区域掩膜与整笔删除。整笔删除使用扫过的线段命中，不能只检查离散点；区域掩膜不当作普通笔画删除。完整擦除手势是一条撤销记录，取消恢复原始数组；PDF 区域预览画在历史墨水层，取消重绘去除预览。

PDF 和白板笔迹在加载时验证结构与坐标。损坏数据保留原始字段并显示错误，禁止编辑和空白覆盖，不静默丢弃坏笔画后重新保存。只读退出及未修改的另一分屏仍可完成，不要求覆盖坏数据才能返回。

稿纸方格/横线/白纸按钮已接入独立底纹层，随平移缩放并限制可见线数，橡皮不擦底纹；底纹选择是当前阅读会话设置。关闭有待保存笔迹的稿纸分屏先等待主文档与稿纸写入，失败留在原分屏。恢复原件、打开搜索或整理新资料前需完成当前批注保存。

## 验证与复测

源码回归使用平台替身，验证实际服务和视图方法；不会模拟 ArkUI 手势竞争、PDFKit 设备渲染或笔身事件。新增独立 `tools/verify-pdf-chain.mjs` 并接入 GitHub 检查，涵盖复制短写/同步失败、缺源、首页渲染失败、导入及重读、恢复取消/失败/页数不匹配、工具与模式切换、最后一笔、过期保存及位图释放。

本轮 354 项工作流、30 项 PDF 专项与 11 项发布规则通过；生成隐私资源和 68 份图标资源一致。另有 6 项 SDK 编译后交互回归检查菜单参数转换、选中状态、顶栏替换及分屏入口；仍不模拟原生命中与手势竞争。真实 PDF 结构及逐页渲染检查与平台替身测试分别记录，不能将替身结果当作物理设备导入/识别证明。

干净 Release APP 构建通过；产物为同时声明 phone/tablet 的未签名开发包，保留现有 SDK 弃用及权限检查提示。仓库版本和已发布的 1.0.3 标签没有更改，后续正式发行应按发布流程升级版本并签名。

真实文字 PDF 与两页纯图像快照 PDF 均用 Poppler 渲染检查；快照确认两页、含图像、无文字层，生成工具为 `tools/create-snapshot-pdf.py`。只有在“设置 → 使用指引”主动导入才加入资料库，不用于替代用户缺失的原件。

设备验收步骤：

1. 断网、无 Key，在使用指引分别导入两份测试 PDF，在“示例资料”打开，检查两页内容与真实页数。
2. 进入批注，画笔/荧光/橡皮分别操作，撤销/重做；切页、连续/单页、缩放、手指开关，检查笔迹对应页面。
3. 在落笔和擦除中点击返回，确认进入只读且文件保留；再次返回，重开及重启后检查最后一笔。
4. 对缺少原件的旧资料重新关联；取消、不一致页数、不可读 PDF 和存储不足均应保留原记录/笔迹，不发布无效来源。
5. 白板和稿纸分别用手指与手写笔书写/擦除；方格、横线随平移缩放，擦除不影响底纹；关闭稿纸及重开检查笔迹。
6. 手机/Pad 横竖屏、键盘打开时检查加号菜单、模型菜单、外点关闭与返回；导入期间连续点击或换会话不挂错引用。

当前开发环境没有可用设备连接。真机上述步骤、笔身双击/轻捏、OCR 识别准确度、后台恢复及实际存储耗尽仍待执行。未签名开发包不替代正式市场签名和上架验收。
