# 墨语体验设计方案（2026-10-09）

基线：v1.0.3。先形成整体体验方案，再实施基础改进；手机保留五项底栏，Pad 共用图标与功能。目标是学生能够独立完成“收集 → 整理 → 阅读记录 → 复习 → 查找 → 备份”，不能用更多按钮或未开放的云服务代替完整流程。

## 调研与取舍

| 依据 | 可借鉴的原则 | 墨语落地方式 |
| --- | --- | --- |
| [Notion 侧栏](https://www.notion.com/help/navigate-with-the-sidebar)、[设置检索](https://www.notion.com/help/workspace-settings) | 导航分区、常用入口与深层设置分离、设置能按关键词找到 | 保留底栏；设置按工作空间、连接、安全与帮助分组，搜索显示目标详情页 |
| [Notion 页面布局](https://www.notion.com/help/layouts) | 正文与属性分离，信息按组展现 | 阅读正文为主，属性和工具按任务展开；不在首页堆放全部配置 |
| [Obsidian 外观](https://obsidian.md/help/appearance)、[搜索](https://obsidian.md/help/plugins/search) | 明暗模式与主题独立，检索与当前文档查找职责不同 | 四套语义配色 × 系统/浅色/深色；全局检索保留，设置单独检索 |
| [鸿蒙 Navigation](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/arkts-navigation-navigation-V5) | 页面栈、系统返回、宽屏分栏 | 设置改用 Navigation / NavDestination，手机推入详情，足够宽时目录与详情并排；按实际窗口宽度适配 |
| [Core Vision 文字识别](https://developer.huawei.com/consumer/cn/doc/doccenter-references/api/core-vision-text-recognition-api) | 系统文字识别与生成式模型是不同能力；清晰图像影响结果 | 使用系统 OCR，无需配置大模型；规则排版默认离线，异常保留输入，姓名、数字和公式由用户校对 |

以上是对来源的设计推论。借鉴成熟信息架构，保留校园、本地、手写和鸿蒙特色；不复制 Notion 的团队商业服务或声称等价功能。

## 用户旅程与页面职责

| 场景 | 主路径 | 必须保留的反馈与恢复 |
| --- | --- | --- |
| 收集课程通知 | 首页 → 文字识别 → 选图片/粘贴 → 校对 → 本地排版 → 预览/编辑 → 保存 | 空输入、超长、图片无字、识别不支持、取消、保存失败；原文可追溯，任务逐项确认 |
| 阅读与记录 | 资料库 → 文档 → 阅读 / 主动编辑或批注 → 保存 | 默认只读、保存状态、失败重试、离开保护；不把读者工具混入设置 |
| 校园复习 | 项目/课程 → 资料 → 摘录/题卡 → 复习 | 空课程指向创建或导入，题卡有来源，不自动制造学习内容 |
| 找到内容 | 全局搜索 → 筛选 → 文档；伴读 → 本地检索 → 来源 | 无结果有下一步，检索不冒充生成式回答，来源能打开 |
| 换机或跨端 | 设置 → 备份与传递 → 导出/恢复/附近设备 | 明文范围说明、双方确认、恢复副本；不声称华为账号自动云同步 |
| 调整偏好 | 设置 → 搜索/分类 → 详情页 → 返回 | 可见当前位置；主题立即更新且重启保持；API 草稿离开前保护 |

主导航保留首页、资料库、日程/待办、图谱、伴读及现有手机底栏对应项；设置通过原入口访问。全局导航处理工作空间，详情页处理配置，不新增重复主入口。

## 设置信息架构

- 工作空间：资料库、外观与动效、文字识别与排版。
- 连接：AI 与模型、备份与传递、鸿蒙与设备。
- 安全与帮助：使用指引、隐私与数据、关于墨语。

设置首页只展示入口、摘要和检索。每项进入独立详情；备份保留现有完整导出恢复界面。云 AI/云备份状态仅作为连接详情中的次级说明。API 配置的离开、系统返回和分类切换都执行同一草稿保护，不因分栏导航丢失输入。

## 统一视觉与交互

- 配色：墨紫（延续品牌）、黑白（中性界面）、浅蓝（柔和背景）、蓝白（白底蓝色操作）。明暗选择独立；六十余种工具使用原 SVG，品牌图标不随任意强调色重绘。
- 使用语义色：画布、卡片、次级表面、分割、主/次/提示文字、强调/强调上文字、成功/警告/危险；不要把所有状态都染成主题色。
- 页面正文限宽，手机 16vp 留白、宽屏 24–32vp；控件至少 44vp，说明多行换行，避免固定高度裁剪大字号。标题、说明、主要行动、详情组成稳定层级。
- 卡片用于内容分组，行用于导航；一个分组只设一个主要行动。空、加载、失败、未开放分别显示真实状态及下一步。
- 原生转场为主，减少动态效果时停用设置转场；不在滚动/输入时重复装饰性动画。手写纸色、笔迹颜色、文档自选封面是内容，保留原色。
- 返回按页面层级，不把设置详情留在长父菜单内；未保存模型/识别输入受到保护。窄窗口使用推页，宽窗口分栏，不按设备型号硬编码。

## 无大模型的识别与整理

1. 图片由系统选择器授权，系统 OCR 返回实际文字；不会填充样例作为成功结果。
2. 保留原文：统一换行、补文档标题，保留原顺序、空段、缩进、代码、表格及公式。
3. 学习笔记：仅将明确的独立标题、中文编号标题、项目符号整理为 Markdown 层级，不概括、不补写、不推测事实。
4. “合并图片断行”由用户主动开启，只合并可判断的普通正文，保护列表、表格、代码、公式和空段；复杂多栏图片不能保证阅读顺序。
5. 待办候选排除完成、取消和否定行动及代码/公式；候选默认不选。模糊日期不猜年份，用户可编辑。
6. 预览使用与阅读同一文本解析器；保存保留识别原文。AI 是额外选择，失败落回相同本地排版方式。

## 本轮实施与后续价值排序

本轮实施：设置目录与原生详情导航、设置搜索、主题系统与全界面响应、本地排版差异、断行选项与草稿保持、完善鸿蒙能力状态与操作指引、针对故障和保存的验证。

后续优先验证：断网真机完整旅程、手机/Pad 分屏与大字号、星闪笔/系统分享、备份恢复与 OCR 中文英文样本。进一步产品需求按价值排队：跨资料检索筛选、复习进度与来源、文件批量导入/去重、可配置笔记属性。同步和数据结构迁移必须先设计冲突/恢复规则，再开放自动写入。团队云服务目前无运营条件，不进入承诺清单。

## 验收矩阵

| 范围 | 可自动验证 | 设备验收 |
| --- | --- | --- |
| 主题 | 非法值回退、四套明暗语义色对比、持久化失败不误报成功、保存顺序、资源构建 | 热切换、重启、系统深浅色、不同页面一致性 |
| 导航 | 目录检索与未知路径、API 离开保护方法、ArkTS 编译 | 原生转场/返回、分屏宽度、滚动位置、大字号和键盘 |
| 本地整理 | 无 Key/离线零模型请求；标题/列表/代码/表格/多段公式、OCR 断行、完成/否定候选、失败回退 | 中英图片、旋转/模糊图、长文、断网、识别服务不可用 |
| 完整流程 | 文档/待办写入失败重试、消息/资料生命周期、备份规则、发布资源检查 | 导入→保存→重启→检索→分享→恢复，手机和 Pad 各一遍 |
