# 墨语代码规范与审查准则

本规范说明格式、命名、分层、状态管理与代码审查约定；开发环境和工作流程见[开发指南](DEVELOPMENT_GUIDE.md)。自动工具的实际覆盖范围在下文列明。

## 格式、命名与接口

- UTF-8、2 空格缩进、文件末尾换行；新文本默认 LF，Windows 批处理使用 CRLF。由根 `.editorconfig` 提供编辑器默认值，不整库格式化无关文件。
- 独立 Python 模块遵循 PEP 8 的 4 空格缩进，由 `.editorconfig` 的 `*.py` 覆盖；仅使用标准库时不引入空依赖清单或隐式安装步骤。结构化模型输出先按白名单核验，再进入工作区。
- 类、组件、接口、枚举和类型用 `PascalCase`；方法、变量、属性和参数用 `camelCase`；真正不可变的共享常量用 `UPPER_SNAKE_CASE`。文件沿用既有职责名，如 `ReaderCommitPolicy.ets`。
- ArkTS 使用明确类型和有界联合；不通过 `any`、多重类型断言或忽略编译错误绕过模型。外部数据先校验再进入领域模型，未知类型拒绝保存。
- 导出最小接口；注释解释不明显的约束、资源归属和失败原因，不逐行复述代码。待办注明影响和可验证的完成条件。
- 共享序列化字段、数据库键和协议字段视为兼容契约；更名须迁移，不能只改界面类型。不得对依赖字段名的 JSON 开启破坏性属性混淆。

## 分层与依赖

`pages → views/services → common`：页面装配端口和状态；视图通过属性／回调通信；服务负责用例与系统适配；common 不导入上层。服务不能引用页面或视图，视图不能引用页面，禁止循环依赖。

`*Policy` 尽量保持纯函数，时间、随机值与环境通过参数输入；确定性策略不读取文件、AppStorage 或系统时钟。系统 API、权限、图像与文件句柄封装在服务；不要在组件渲染中读库或发请求。当前有历史大文件，按明确用例逐步拆分，不因行数阈值机械拆文件。

## 状态、异步与错误

1. 已持久化数据是事实源，写入成功后再发布“已保存”。失败保留输入、脏标志、重试与原状态；不使用空数组／空字符串掩盖读取失败。
2. 队列捕获不可变输入，执行时读取最新状态；提交只合并本区域字段。阅读位置不更新编辑时间，批注不覆盖正文或封面，稿纸不借用其他笔记身份。
3. 后台结果带文档 ID、请求代次或修订；关闭、切换或取消后拒绝迟到结果并释放资源。重复点击只提交一次或通过明确幂等键处理。
4. 长 JSON、PDF 解析和适合的计算移入 TaskPool；文件与 Base64 优先异步。限制队列并发、缓存、输入大小和输出数量，不能把重任务简单包装成 Promise 就认定离开主线程。
5. `catch` 必须恢复、反馈、重试或说明可忽略原因；不要吞掉保存、迁移与校验错误。对外文案说明可采取的操作，日志不含学习原文、密钥或私人路径。

## 数据、文件与资源

- 保存正文使用已有原子文件适配器，完整写入并同步后替换；RDB 相关集合用事务提交。明确二者并非联合事务。
- 损坏数据阻止空值覆盖；迁移先校验，保留旧副本，未知未来版本拒绝打开。禁止通过重置资料解决结构不匹配。
- 永久删除先记录待清理日志，再幂等清理；附件仍被引用时不得删除。失败保留重试线索。
- 文件路径限定在允许目录，导入只读取用户选定内容；备份采用字段白名单、大小上限、结构和附件完整性校验，不读取包内任意绝对路径。
- 文件、PDF 文档、PixelMap、Canvas 缓存、订阅、计时器和任务均有明确持有者与释放时机。成功、失败、取消和过期结果分别覆盖。

## 原生界面与无障碍

复用主题、图标和阅读工具，操作区至少 44vp；图标按钮有可读名称，状态不只用颜色表达。手机／平板、大字体、横竖屏、深浅色、键盘和减少动态分别验收。正常返回等待保存，不新增无意义确认弹窗；破坏性清空需明确对象和确认。

当前视觉参照及具体交互见[设计规范](DESIGN_REVIEW.md)。系统 API 调用要考虑最低 API 24 的运行时能力差异；API 26 专属能力不能只凭编译可用就默认所有设备支持。

## 依赖、安全与云边界

当前客户端无互联网权限、无广告分析和中心账号。新依赖说明用途、许可证、体积和维护成本，更新锁文件；未经本轮需要不升级 SDK。第三方许可证原文随相关资源保留，见[依赖清单](DEPENDENCIES.md)。

云服务和云端 AI 仅按[独立方案](CLOUD_AI_DESIGN.md)后续实现。接入前更新产品范围、权限、隐私、凭据和测试；禁止提交签名、Token、用户备份或私有课本。不得把存储加密宣传成推理方看不到明文。

当前主程序只补齐本地学习能力：`LearningProgressPolicy` 根据已提交资料与自测反馈生成概况和到期队列，时间显式传入；它没有传输、服务账号或模型调用依赖。`cloud/ai/` 继续独立，禁止在客户端导入、打包或暗中启用。派生统计不能把阅读末页或一次自评改写成客观掌握结论。

## 哪些规则已有自动检查

| 入口 | 实际覆盖 | 不覆盖 |
| --- | --- | --- |
| `.editorconfig` | 支持该文件的编辑器格式默认值 | 不是历史代码自动格式验收 |
| `code-linter.json5` | DevEco 性能、TypeScript 与现有密码学安全规则配置 | 仅有配置不代表本轮运行 lint；须保存实际 IDE 报告 |
| `tools/verify-architecture.mjs` | 下层不反向引用、相对导入循环、关键策略无平台／时钟副作用、release 样本隔离 | 不推断所有函数纯度或业务正确性 |
| `tools/verify-local-release.mjs` | 源码可达、权限、当前功能隔离；`--local-docs` 检查文档链接和存档完整性 | 不保证设备可用性 |
| 现有工作流、仓储、PDF、编辑生命周期专项 | 实际输入输出、失败保护、合并归属、SQLite 事务与迁移 | 不是系统模拟器和真机结果 |
| `tools/verify-documentation.mjs` | 公开文档完整性、仓库内链接和本地材料隔离 | 不核实外部网页或产品运行质量 |
| `tools/verify-ai.mjs` | 独立原型的真实 SQLite、课程隔离、引用、发送确认、状态、失败与导出边界 | 模拟模型传输，不证明真实推理质量或具备托管能力 |
| `git diff --check` | 本次跟踪文件差异的空白错误 | 不代替代码审查或 ArkTS 编译 |

统一入口见[开发指南](DEVELOPMENT_GUIDE.md)。仅文案／可逆低影响样式不写复制实现的测试；保存、迁移、并发和提交门槛必须有失败用例。检查失败先定位并修复，不能删除断言或放宽边界只为让结果变绿。

## 审查完成标准

当前仅 `LearningResult` 类型和 `LearningResultPolicy` 策略作为明确未启用的准备模块保留，生产入口不得引用；源码范围检查精确列出这两份文件，架构检查约束隔离。共享结果契约的修改须同步 Python／ArkTS 样本与回归，并通过单独测试目标编译。该例外服务于已授权的接入准备，不适用于任意未使用代码。

审查人须能说明：解决什么问题、字段归谁所有、失败时保留什么、取消后是否还能更新、资源谁释放、是否破坏旧资料、真实运行了什么验证、哪些设备项待验。提交说明写问题、行为变化、实际检查和限制。规划、已实现、自动验证和真机验证使用不同状态；公开产品／开发文档随源码维护，操作交付记录和个人证据留在本地。
