# 墨语校园应用价值评估

日期：2026-10-04。适用对象：高校在校学生。按参赛者提供的商业价值 40、创新性 30、完成度 20、应用规范性 10 分评审结构规划；分值是评审权重，不是项目已获得的分数。

## 产品价值主张

学生把讲义、截图和笔记整理为课程资料，回到原文核对知识点，再创建题卡、自测并安排下次复习。手机用于随时查阅与复习，Pad 用于阅读和手写，两端复用服务与图标体系。

首发采用本地保存、离线关键词检索、手动题卡和可选自配 AI。团队当前不运营云盘或 AI 服务，不要求注册应用帐号。备份经系统文件选择器导出，用户可自行选择系统支持的存储位置；这属于手动备份，不是自动云同步。

## 当前可复现的演示

1. 用有权使用的课程截图执行图片 OCR，校对姓名、日期、公式与否定词，使用本地排版保存到课程分类。
2. 导入真实 PDF，在阅读器“更多 → 提取 PDF 文字”选择页范围。每批最多 30 页，扫描页可选择端侧 OCR，校对后保存；未提取的页面不进入检索。
3. 搜索该页中的概念，打开真实来源页；启用已配置的模型时，展示回答的引用片段与页码，再回到 PDF 核对。
4. 首页课程研读进入题卡。离线手动创建问题与答案；可选 AI 生成 1～6 题预览，匹配原文的题目仍需人核对答案后保存。
5. 先回忆、再看答案，选择不会/模糊/掌握；显示总复习次数、遗忘次数与下次日期。间隔是简单可解释规则，不宣称提高成绩或科学诊断学情。
6. “设置 → 资料库 → 本地备份”导出并恢复到副本。重复导入同一文件不重复创建资料或题卡；同一备份内的唯一双链重连，同名或外部链接不猜测。

## 小规模试用方案

先邀请 6～10 名学生，覆盖手机与 Pad，试用一周。人数与周期是建议，尚未招募或完成试用。先观察核心任务，遇到阻断问题就修复，暂不扩展更多工具入口。

- 使用学生有权处理的课程资料；同意参与后记录匿名编号，不收集学号、成绩、私人笔记或 API Key。
- 准备难度与长度接近的两组资料，每组执行整理、查证、自测三项任务。交替安排“原方法 → 墨语”和“墨语 → 原方法”，减小熟悉题目带来的影响。
- 分别记录纯离线与开启 AI 的任务；模型服务、模型名、是否 OCR、设备与网络情况作为条件记录，不把不同条件直接混成效率结论。
- 用秒表和观察表记录耗时、错误与需要帮助的次数。使用满 7 天后询问实际使用天数、复习行为、最有价值功能与放弃原因。当前应用没有接入团队行为统计服务。

| 指标 | 记录与计算方式 | 初步判定条件（待验证） |
| --- | --- | --- |
| 整理效率 | 同等难度任务的原方法耗时与墨语耗时；报告中位数和每人的变化，失败任务单列 | 中位数耗时减少 20% 是试验目标，不是现有结论 |
| 首次任务完成率 | 不受帮助完成核心任务的人数 / 尝试人数；同时记录阻断步骤 | 建议目标 ≥ 80%；小样本只报告人数和比例，不外推全校 |
| 来源核对 | 抽查题卡引用、答案与原文分别是否一致；核对跳转是否到正确笔记/PDF 页 | 引用匹配、答案正确、页面定位分别计数；引用匹配不等于答案正确 |
| 复习持续性 | 7 天内使用天数、完成反馈的题卡数、再次主动使用的人数 | 先找出放弃原因，再决定增加提醒或付费功能；不能用自评次数替代成绩 |
| 可靠性 | 保存后重启、备份恢复、取消和重试任务的成功/失败数；附问题记录 | 正式发布前核心资料不得出现未处理的数据丢失或恢复失败问题 |
| 使用成本 | AI 控制台实际消耗、操作所需时间、团队每周维护工时 | 离线任务没有模型调用；AI 消耗来自用户所选服务，需实际记录 |
| 付费意愿 | 询问为哪个具体价值付费、一次性/订阅偏好与可接受范围，并问拒绝原因 | 口头意愿是需求线索，不计为付费用户或收入 |

## 可持续商业路径

首发免费验证核心学习需求。获得留存和具体付费意愿后，再评估一次性付费的本地进阶能力、课程模板或机构授权；必须先明确能交付的价值、内容版权与维护成本。收费、支付、模板商店和机构协作当前均未实现。

先计算“实际收入 − 退款及实际交易成本 − 固定工具费用 − 维护/支持工时成本”，再谈收益。尚未有收入、用户规模或合作校方证据，参赛材料不得填入虚构的市场验证。

云端 AI 与云盘仅作为后续候选方向。只有找到稳定合作方、明确单位成本、责任边界和用户需求后才评估；不把免费 API、个人服务器或学生团队无限补贴当成商业基础。接入外部服务前仍须更新隐私说明与审核材料。

## 范围与发布边界

- 原 PDF 批注目前保存在应用笔迹数据中，未实现写回原 PDF 的嵌入批注导出。
- Word 正文解析、完整公式/表格排版、跨设备自动同步、自动提醒和付费系统尚未完成，不列入已交付价值。
- 本轮服务回归与 ArkTS 编译可证明具体逻辑和可构建性；尚不能证明真机动画流畅、学习成绩提升或应用市场审核通过。
- 本工程当前使用 HarmonyOS 的系统 Kit；如赛事要求独立 OpenHarmony 运行证明，需要另行核对规则并验证目标系统，不能用 HarmonyOS 构建结果替代。

## 调研依据

产品取舍参考 [Goodnotes Study Sets / Smart Learn](https://support.goodnotes.com/hc/en-us/articles/7353756529551-Getting-Started-with-Study-Sets-and-Smart-Learn) 的自测与复习流程，以及 [Google 资料学习工具](https://notebook.google/students?hl=en-US) 的来源核对方式。以上功能在其他产品已有实践，本项目的创新主张应落在校园流程与鸿蒙设备使用方式，而非宣称首创。
