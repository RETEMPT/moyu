# 文档智能提取与鸿蒙端侧推理

核验日期：2026-10-09。目标是无服务器也能提取、校对并保存课程资料；本轮追加到 PR #4。

## 能力与取舍

鸿蒙支持端侧模型推理。MindSpore Lite Kit 提供模型转换与部署，并可经 NNRT 使用兼容的底层芯片；实际后端取决于模型算子和设备。[华为官方说明](https://developer.huawei.com/consumer/cn/sdk/mindspore-lite-kit/)

Marker 当前工程需要 Python、PyTorch 和 Surya 推理后端；完整工程不能直接装入 ArkTS 应用。这不代表鸿蒙硬件不能推理。端侧移植需要模型导出、算子适配及文档处理重写。[Marker 项目](https://github.com/datalab-to/marker)、[模型装配源码](https://github.com/datalab-to/marker/blob/master/marker/models.py)

现有 SDK 有 MindSpore Lite 接口，但仓库没有已转换的 Marker 模型，也没有目标设备的算子、内存和精度验证。本轮实现的是 **Marker 输出互通**，未实现 Marker 模型的 NPU 部署，不在界面显示虚假的硬件推理开关。系统 OCR 已接入，不能据此认定它在某台设备上使用了 NPU。

## 已实现的导入链路

| 输入 | 实际处理 | 保存前检查 |
| --- | --- | --- |
| 图片 | 鸿蒙系统 OCR | 识别结果进入文字草稿，用户核对数字、姓名和公式 |
| PDF | 本机 PDFKit 文字层；空文字页尝试系统 OCR | 每次 1–5 页，提取不自动视为校对索引 |
| Markdown / TXT | 本机读取 | 保留原顺序、表格与公式源文 |
| Marker Markdown 响应 JSON | 提取字符串 output / markdown | 拒绝失败响应、结构树 JSON、空结果和超限文字 |

首页“提取内容”或设置“文字识别与排版”进入统一面板，选择“导入 PDF / 文字 / Marker 结果”。PDF 默认第 1 页，可填写范围；文件最多 20 MB，文字文件最多 1 MB，每次整理最多 12000 字。超过限制应分段导出或缩小页范围，原草稿保留。

Marker CLI 的 Markdown 可直接导入；服务器返回的 `format: markdown` 成功响应也可作为 JSON 文件导入。这里只读取文件，没有调用服务器。CLI 的配套图片、结构 JSON、HTML、ZIP 和原始 DOCX 等没有通过这个入口直接解析；图片资源须另行保管，不能保证外部相对图片链接可显示。格式依据 [官方服务器源码](https://github.com/datalab-to/marker/blob/master/marker/scripts/server.py) 和 [输出源码](https://github.com/datalab-to/marker/blob/master/marker/output.py)。

PDF 使用临时沙箱副本，逐页提取、释放位图/页面，并在结束、失败或取消后清理副本。重复点击不会启动第二次选择；关闭后的结果不会追加。导入错误不覆盖输入；整理预览可编辑正文并核对原文，任务逐项勾选后才创建。

“AI 整理”默认关闭。只有有效模型配置、可用密钥及该地址的发送授权都成立时可开启；恢复草稿时仍重新检查。开启会把文字发送给用户配置的服务；关闭使用离线规则。模型调用失败时保留原文并显示本地降级说明。已有图片、PDF 和文字提取不要求大模型。

## 工具与效率

沿用实际 Function Calling 链路，共 15 项工具：6 项查询及 9 项确认后修改。新增重命名、更新文字正文、收藏/置顶及待办状态；保留新建笔记/待办、标签、分类和双链。笔记清单与长正文支持分页，返回 ID、版本及下一起点，避免只让模型看到最前面几篇资料。

写工具逐次确认并等待持久化成功。AI 修改排队后读取最新状态，正文更新检查读取版本，拒绝 PDF/手写/原件正文和正在打开的编辑器。文件成功、快照失败时尝试恢复旧正文；失败不会发布新界面状态。这仍是分步保存，不能承诺断电或跨全部 UI 操作的联合事务。

工具需要支持 Function Calling 的 OpenAI 兼容/自定义流式模型以及相应权限。Gemini/Anthropic 目前没有此原生工具链；外部 MCP 客户端没有在本轮接通，不能把内置工具称为任意插件执行。回收站、密钥、设置和文件系统没有开放任意模型修改权限。

首页资料按 12 项分批展示，筛选排序复用同一资料快照缓存；卡片右上角的封面快捷按钮删除，更换封面保留在卡片菜单。文字提取限页、模型读取限段、逐页资源释放用于控制工作量；不以这些改动代替设备帧率证明。

## 完整端侧移植仍需完成

1. 固定 Marker / Surya 版本和权重来源，先选一个版面检测模型导出，保留输入尺寸、坐标恢复、阅读顺序和解码规则。模型权重许可与代码许可不同，打包前须分别核对。[代码及权重说明](https://github.com/datalab-to/marker#commercial-usage)
2. 转换为对应 SDK 可加载的模型，逐项处理动态形状与不支持算子。Converter 支持源框架不表示任意模型都可转换或全算子都能由 NPU 执行。[转换工具](https://www.mindspore.cn/lite/docs/zh-CN/master/converter/converter_tool.html)
3. 重写推理输入/输出及 PDF 页面处理，与原模型对照中文多栏、扫描、表格、公式样例。版面检测通过并不等于 OCR、公式与全部 Marker 流程通过。
4. 在实际手机和 Pad 上记录峰值内存、首轮/连续耗时、耗电、后台/取消行为及 CPU 回退；确认可接受后才公开端侧模型选项。

当前没有已转换的权重和可连接的鸿蒙设备，上述模型转换和硬件性能验证尚未执行。现阶段可用路径是本机提取、离线排版以及已转换 Marker 结果导入，无需团队运营服务器。
